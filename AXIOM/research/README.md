# `research/` — لایهٔ دانش (غیر‑هنجاری)

این پوشه **بخشی از مجموعهٔ طراحی AXIOM نیست**. هیچ آزمون، دروازه یا بندی از `docs/AX-00…AX-18` به آن ارجاع
نمی‌دهد و تغییر محتوایش هیچ تأثیری بر رفتار سیستم ندارد. ثبت رسمی این وضعیت: `AX-18` — **ADR-026**.

## چرا وجود دارد

مالک قصد دارد یک **دایرةالمعارف منابع** (مقالات، کتاب‌ها، مقررات، مستندات فنی) حول مفاهیم واقعی
سیستم‌های کوانت/مؤسسهای بسازد. جمع‌آوری بدون ساختار، به آرشیو بی‌فایده تبدیل می‌شود؛ پس این پوشه
ساختار و ابزار جست‌وجو را فراهم می‌کند.

## فایل‌ها

| فایل | نقش |
|---|---|
| `CONCEPT_ATLAS.md` | اطلس مفاهیم: ۱۲ موتور قدیمی (E01–E12) + ترجمهٔ مؤسسهای هرکدام، ۱۲ موتور واقعی استک مؤسسهای، کتابخانهٔ کانونی، راهنمای شکار منابع، و دام‌ها |
| `build_index.py` | **تک‌منبع**: از یک جدول، هم فهرست ماشین‌خوان و هم بستهٔ کوئری را می‌سازد (`--check` هرگونه انحراف را رد می‌کند) |
| `concept_index.json` | ۲۴ مفهوم با: مترادف‌ها، خانواده، موتور میزبان، وضعیت (`CORE`/`ADJACENT`/`SPECULATIVE`)، ارجاع به بندهای AX، منابع کانونی، کوئری‌ها |
| `search_queries.txt` | ۱۲۱ کوئری آمادهٔ کپی/پیست؛ هر خط با شناسهٔ مفهوم شروع می‌شود تا نتیجه به مفهوم درست برگردد |

```bash
python3 research/build_index.py           # بازتولید فایل‌های تولیدشده
python3 research/build_index.py --check   # باید بنویسد: research index check: OK
```

## نحوهٔ افزودن یک مفهوم جدید

۱. ردیف تازه در جدول `C` داخل `build_index.py` اضافه کنید (شناسهٔ جدید، مثلاً `C01`).
۲. سه چیز الزامی است: **مترادف‌های انگلیسی** (برای جست‌وجو)، **وضعیت** (`CORE`/`ADJACENT`/`SPECULATIVE`)،
   و **ارجاع به بند AX** (یا `—` اگر هنوز وارد طراحی نشده است).
۳. `--check` را اجرا کنید تا تولیدها هم‌خوان شوند.

## وضعیت‌ها — معنی دقیق

| وضعیت | معنی | رفتار پیشنهادی در دایرةالمعارف |
|---|---|---|
| `CORE` | مفهوم با ادبیات مستقل و تکرارشده | ثبت کامل: منبع اولیه + تکرارها + محدودیت‌ها |
| `ADJACENT` | روایت خرده‌فروشی از یک پدیدهٔ واقعی (مثل FVG ↔ شکاف نقدینگی) | ثبت با برچسب «فرمول‌بندی غیرشاهد» و ارجاع به نام مؤسسهای |
| `SPECULATIVE` | بدون ادبیات مستقل | فقط به‌عنوان فرضیهٔ قابل آزمون (`AX-10` بند ۲) |

## قانون طلایی (تکرار عمدی، چون مهم‌ترین قاعدهٔ این پوشه است)

هیچ چیزی از این پوشه **مستقیم** وارد کد یا طراحی نمی‌شود. مسیر ورود، همان مسیر رسمی است:
`AX-05` بند ۲ (مکانیزم + آزمون اطلاعات حاشیه‌ای + FDR) → `AX-10` (پیش‌ثبت + نردبان L0–L6) →
`AX-15` (پارامتر با شناسه و کلاس) → `AX-18` (ADR در صورت تغییر رفتار)، و سپس `AX-14` (آزمون‌ها و دروازه‌ها).
این همان قاعدهٔ `AX-16` بند ۹ است: «هیچ عددی بدون ارجاع رجیستری، هیچ رفتاری بدون تصمیم ثبت‌شده».
